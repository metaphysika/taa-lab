## Format

Each trace has `id`, `title`, `contracts`, and optionally `targets`, `spec_refs`, `setup`, `steps`, `final`, `variants`, `parameters`, `notes`. W0's `conventions` define the step phases, setup merging, variant modes (`continue` or `replace`), the default token lifetime, the revision convention and the outcome vocabulary.

A step entry has a step number and at most one action: events, a proposal, or an execution, with its own `expect`. Entries sharing a step number must be listed in phase order (events, then proposals, then executions); the validator enforces both rules. Several entries may share a step number; they run in phase order (events, duty engine, proposals, executions), and in listed order within a phase. Every duty id is a quoted string, such as `"D_refund(CL1,120)"`.

## Rules for using these traces

1. Sol maps W0's abstract names to implementation names in a table filed with the build; Claude reviews it.
2. Sol never edits an expected outcome to match either implementation. A disagreement is filed as a discrepancy naming the trace, the expectation and the observed result.
3. A trace changes only for a specification reason, recorded in the CHANGELOG with the design section relied on, and reviewed by Astra or Claude before use.
4. Expected outcomes are never generated by the reference model.
5. Any skipped or unimplemented assertion is reported as incomplete coverage and does not count toward acceptance.
6. Astra's spot review covers at least one trace per contract B1 to B5, plus T23 (rollback), T24 (expiry), T14 and T39 (order association), and T20 to T22 (duty reopening).

## Changes from v0.1, following Astra's review

- Duty ids quoted everywhere; strict validator added.
- Q1 to Q9 decided in the clarification note, so no `pending_spec` assertions remain. Q2, Q3, Q7 and Q9 follow Astra's changed readings; Q8 revises DU4.
- Trust boundary split into create and correct permissions by field; chargeback, withdrawal, resolution, order and report kinds declared.
- `committed: none` replaced by `action_executed: false` (gateway transitions such as reports may still occur) and `transaction_changes: none` (full rollback).
- W0 now states the partial-delivery rule, reserved questions and their resolver, the interim rule, conflicts for implicated parties, the reporting lifecycle, claim filing time, default token lifetime and variant semantics.
- T34 seeds an agent note instead of permitting a contradicted report; T34c shows that report is itself prohibited.
- T13R uses a declared reserved question; T24b isolates token expiry; T36b uses two authenticated orders; T37 adds versioned acknowledgment and a supplement; T39 added.
