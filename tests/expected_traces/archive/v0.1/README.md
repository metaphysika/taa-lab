## Trace format

Each trace has an `id`, `title`, the `contracts` it exercises, optional `spec_refs`, a `setup` (changes to W0), `steps`, and optional `final`, `variants` and `parameters`.

A step may contain, in this order: `events` (simulator inputs, applied first in the step), `propose` (an agent proposal), `execute` (use of a token; `token: next` means the token from the immediately preceding PERMIT), and `expect`. `expect_after_propose` and `expect_after_execute` check state after that action when a step has more than one. Several steps may share a step number; they run in listed order within that step.

Expectation keys are checked against the simulated world and the ledger, not only the log:

- `disposition`, `rule`, `token`, `committed`, `duties`, `duties_created`, `case_*`, `revision` (`R+` advances, `R=` does not).
- `not_permitted: true` means anything but PERMIT, with no token. It is used where the design does not yet fix the disposition name.
- `pending_spec(Qn)` marks an expectation that depends on a spec question below. Checkers skip that single assertion until the question is answered, then this file is versioned with the answer.

## Rules for using these traces

1. Sol maps W0's abstract names to implementation names in a table filed with the build; Claude reviews the table.
2. Sol never edits an expected outcome to match either implementation. A disagreement is filed as a discrepancy naming the trace, the expectation and the observed result.
3. A trace is changed only for a specification reason, recorded in `CHANGELOG` below with the design section relied on, and reviewed by Astra or Claude before use.
4. Expected outcomes must never be generated by the reference model.
5. Astra's spot review covers at least one trace per contract B1 to B5, plus rollback (T23), expiry (T24), order omission (T14) and duty reopening (T20 to T22).

## Spec questions found while writing

Writing the traces surfaced nine points v0.3 does not settle. Each has a proposed reading; affected assertions are marked `pending_spec`. These should be answered in a v0.3.1 note before the affected stage is built.

| Q | Question | Proposed reading | Traces |
| --- | --- | --- | --- |
| Q1 | What disposition does an act get when a support rule is violated (the facts establish the opposite) and no alternative exists? The disposition table covers unknown facts (HOLD) and prohibitions, not this. | Add REFUSE: not permitted, no report duty, the agent receives the violated rule and facts. | T03, T17, T28, T32, T34, T35, T38 |
| Q2 | Can a duty rule release its own duty on a record, with no party acting, when the support that opened it becomes violated or the claim is satisfied another way (chargeback, duplicate)? | Yes; the release cites the record and reopens under B4 if that record is later corrected. | T03, T22, T28 |
| Q3 | How does the gateway decide which stored order a proposal answers? | Every open order addressed to the acting party whose scope covers the computed act (same tool and claim) is associated, whatever reference is cited. A cited reference that does not cover the act is rejected and logged. | T14, T15 |
| Q4 | Can an identical proposal on an unchanged snapshot yield a second live token? | No. It returns the existing token. | T12, T29 |
| Q5 | Does a misuse attempt by the wrong actor consume the token? | No. It is logged, R=. | T16 |
| Q6 | What happens to a reviewer answer to a question that is not reserved? | It is not written as a resolution record; it is logged and changes nothing, R=. | T18 |
| Q7 | Does a token's own expiry advance the revision? | No. Only that token becomes void; token state is protocol state, like issuance. | T24b |
| Q8 | When a voluntary transfer offer goes unaccepted and the owner still holds authority, who owns the duty? | The offer lapses and the original owner keeps it. A duty becomes unowned only when its owner has lost authority and the fallback declines. | T31 |
| Q9 | What counts as the same matter for report deduplication when the issuer repeats a wrongful order? | Same issuer, same prohibited act: one report, with the repeat order added to it. | T37 |
