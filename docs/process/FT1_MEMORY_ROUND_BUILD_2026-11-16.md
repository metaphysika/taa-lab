Evidence: tests/test_ft1_memory.py, tests/test_ft1_evaluate.py and tests/test_ft1_throughput.py contain CPU fixtures. This is code only, no run, $0.

Checked: synthetic OOM tracking, three-consecutive stop, receipt refusal, plan-only notebook, public ladder continuation and token parity. Validation totals are reported in the PR. Not checked: real attention dispatch, GPU memory reclamation, actual fit, speed or output parity. No GPU, model, Kaggle, Modal or workflow execution occurred.

The shared evaluation/throughput loader logs requested and configured attention implementations (including text_config), torch and transformers versions. These are configuration observations; they do not establish which low-level CUDA kernel dispatched.

Evaluation catches CUDA OOM and equivalent RuntimeError text during generation, releases local tensors, collects garbage and empties the CUDA cache after leaving the exception scope. The journal records mechanical_oom, prompt token count, turn index and cell identity. Prior turns remain retained. The failed episode is never assigned a conduct label or retried. Test parts continue to the next cell. Three consecutive OOM cells stop the part with stopped_mechanical_oom; a successful cell resets the streak. Three permits isolated large episodes while bounding repeated failures. Test cells alternate action and knowledge; three consecutive OOM cells therefore include a short knowledge prompt, which suggests a broken memory state rather than only a long action history. Unattempted cells are not fabricated as unknowns. report.json and metadata distinguish stopped from complete and count OOMs separately.

Acquisition and format gate failures are counted separately as mechanical OOMs. The gate continues unless three consecutive episodes OOM; any OOM or context-limit failure leaves the gate gate_mechanical_unknown with acquired=null, without recomputing the prescribed scoring thresholds from missing replies. It stops evaluation, including base evaluation, with GateDecisionRequired. Chris must record the decision on eligibility and reruns; this build adopts no policy for either. Aggregated reports show the status separately and withhold predictions pending that decision. gate.json is still written. Scoring code and training code are unchanged.

The new fit_limit phase requires a separate exact-commit receipt with phase=fit_limit. Its local stager defaults PLAN_ONLY=True, internet off, one visible T4 and no FT1 data, sealed cases or adapters. It binds public execution sources without opening sealed.py. Stage after committing:

Each eager/sdpa backend loads a fresh untrained NF4 base and measures public rendered prompts trimmed to 2500, 4000, 6000, 8000, 10000, 11000, 12000, 13000, 14000 and 16000 tokens. It forces exactly 1024 new greedy tokens, ignoring EOS, to test the full output allowance. These are synthetic speed inputs, not evaluation episodes. After the first OOM, the SAME loaded model re-runs the 2500-token rung and journals recovery_check with fit/OOM, peaks, retained IDs and equality to its first pass. It then sends a public oversize prompt through evaluation generation_functions itself, journalling evaluation_oom_probe. The probe uses the first failed rung capped at 15360 tokens, plus the normal 1024 output allowance, to avoid preempting CUDA allocation with the context guard. It may fit: the event reports the observed outcome without claiming an OOM was exercised when none occurred. The ladder then stops climbing; the other backend is still attempted. Later unattempted lengths have no invented fit status. A cooperative 75-minute deadline includes loading and checks each benchmark decoding step; the evaluation-path probe checks at reply boundaries, so an active probe reply or forward can overrun. Handled interruption retains events, metadata and manifest.

After each load and each benchmark cleanup, memory_allocated, memory_reserved and total_device_memory are journalled (after_cleanup on rung results or failures). OOM cleanup happens after leaving the original exception handler, releasing its traceback. CUBLAS_STATUS_ALLOC_FAILED and CUDNN_STATUS_ALLOC_FAILED are also recognized. Attention readback checks both text_config and top-level config; a mismatch is flagged and measurement continues.

Measurements include peak allocated/reserved bytes, prefill seconds, decode tokens/s (excluding the first generated token, which comes from prefill), generated token IDs and prompt hashes. SDPA records first divergence against eager on identical prompts; unavailable references are explicit. Equality has a null divergence; a length mismatch diverges at the shorter length. Parity also records first divergence through the first end-of-turn token (inclusive) in each sequence, while preserving the full IDs. This is descriptive parity, not a correctness gate.
