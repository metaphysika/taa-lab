# Offline cross-arm protocol v0 — before evaluation

Scope: ten existing W0 development programs and four unchanged scripted controllers.
Authority: C1–C4 and approved Q1–Q13; Q14–Q16 remain pending.
Keys: Claude's frozen dispositions only; no model output creates a semantic key.
Oracle: independent reference duty relations over actual records and operations.
Review: a separate C3 PR, Claude review and green CI; no empirical H3 claim.

[PROTOCOL] Arms: ordinary TAA, C1, C2 primary, C2 diagnostic, strongest conventional
SQL, frozen-contract TraceGrant reconstruction, floor and static permissions.
The ten programs are the existing catalog's five reviewed pairs; no new task or
TraceGrant contract is selected after outcomes. Run the same four controllers,
source setup, event ordering, registered interface and proposal-origin bindings.
All run through `reference_runner` and its independent full-state Observer.

[PROTOCOL] Floor accepts registered/schema-valid acts. Static permissions check
one complete initially live grant path, acting party, registered tool, customer
scope and per-call cap, at proposal and execution. Initial paths/scopes/caps are
fixed; no live revocation, support, cumulative cap, reporting or duty guard is
added. Both perform duty offers, acceptance, messages and closure as ordinary
business writes, including repeats. They have no security tokens or duty ledger.
Proposal routing handles are simulator intent references, not authorization or
single-use capabilities. No proposal without an execute entry is performed.
Receipts for these arms identify an intent and have no security-token field;
the common audit verifies actual effects, actor, revision, exactly one business
operation and unchanged empty token collections. Token-based arms retain their
existing consumption/receipt audits unchanged.

[PROTOCOL] The TraceGrant policy, contracts, budgets, evidence admission, one-shot
certificates and final-answer gate remain the reviewed implementation. Its common
runner adapter adds no TAA authorization, duty engine or invalidation feature.
A contract does not authorize duty tools merely because the common registry does.
This is still a local reconstruction, not the authors' evaluated configuration.

[PROTOCOL] Every arm is scored by one external oracle, never its internal duties,
resolution statuses or internal allocation ledger. The oracle uses the independent
reference duty/proof relations and actual evidential records, all their versions,
notices, authenticated host messages and observed committed business operations.
The oracle's normative routing transitions do not count as actual deliveries.
Acknowledgment discharges only a report that the arm actually dispatched, binding
id, version, recipient and matter. Report artifacts are physical persisted report
records and dispatch log entries; SQL's committed versioned report relation is its
abstract dispatch artifact. Internal duty rows never prove discharge or transfer.
Acceptance and offers are reconstructed from committed acts/authenticated messages,
checked against normative standing. Unresolved/overdue/unowned duties and closure
with an unresolved duty are scored identically, without trusting an arm's claim
that it completed a case. Missing observation vocabulary is incomplete coverage.

[PROTOCOL] Semantic labels require the exact source proposal identity (trace,
entry-origin, actor, tool and arguments) and the same representation-neutral
pre-action context as the validated ordinary-core key follower. The baseline
contributes fingerprints only; no baseline outcome becomes a new key. Canonical
context includes business record histories (kind, version, evidential flag and
semantic fields), current grants, stored orders, case closures, delivered notices
and the external oracle's duty state. Serialization metadata, security-token IDs,
certificates, internal ledger encodings and audit-chain hashes are excluded.
Native resolution envelopes are decoded to their stored question, answer,
resolver and evidence; native identifier prefixes are mapped one-to-one. Unknown
or ambiguous mappings are unassessed/incomplete, never silently equivalent.
Changed contexts and extra adversarial requests remain unassessed. No numerical
tolerance or post-results relabeling is permitted. Actual effects and duties are
reported even when their semantic classification is unassessed.

[PROTOCOL] Reports separate attempted/committed keyed wrongful acts, keyed lawful
opportunities and withholding, gateway over-refusals, unassessed actions, actual
refund totals/notices/closures, and externally derived unresolved, overdue,
unowned, reporting and improper-closure counts. Matching the strong conventional
arm is success for both. Differences are bounded implementation observations.
Frozen fixtures, keys, reviewed controllers, regression scenarios, existing
conventional matching rules and POEC contracts stay unchanged. Source assertions
not run in a cross-arm input-only program are reported separately from the common
state audits and existing full acceptance suites; no claim of frozen-key success
is made for a deliberately weaker arm. Regression acceptance remains permanent.
