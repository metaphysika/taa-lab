## Publish a predecessor before starting its successor

[Descriptive] A launched run requires a separate clean, origin-current linked worktree of public branch `experiment-a-evidence`, selected by `TAA_EXPERIMENT_EVIDENCE_WORKTREE` (default `/workspace/taa-experiment-evidence`). It must belong to the run repository, outside the run checkout. It has an `evidence.json` manifest matching `experiment_a.publication.SPEC`. Preparation creates this branch/worktree once, separately from any model run. Missing, dirty or stale worktrees refuse execution. No secret or H file belongs in this worktree.

[Descriptive] Once a child closes, the publisher verifies its checkpoint and the canonical raw root prefix. It scans **every file to be published**, including the root's raw requests/replies/usage/accounting frames, using exactly the PR #38 credential patterns and configured-secret comparisons. Base64 native replies are decoded and scanned as well. A match stops with `evidence_credential_scan_failed` before any copy/stage/commit/push or next episode. No credential values enter errors or evidence. Forbidden H definition/key filenames and symlinks also stop.

[Descriptive] Files live at `runs/<sha256(local-root-path)>/episode-NNNN/` and `runs/<same-id>/root/`. Numbered frames, child checkpoints and existing closed-root checkpoints are copied byte-exact. Existing public files are immutable. Each episode commit contains its child chain and all raw root frames through its closure. During a live segment the root is an explicitly unfinished prefix; after the segment closes, the root summary/closure/checkpoint is also published. A `publication/` chain in the local run retains final-root confirmation events without rewriting the sealed root. Per-episode confirmation events are retained in the root and included in its next publication. All such local chains remain part of the retained evidence for reporting.

[Descriptive] Before starting a continuation, all prior closed root/child chains are backfilled or checked byte-exact against this branch, before any new provider request. This includes the accepted scoreless outage child. This does not rerun, replace, rescore or modify any prior episode. Per-request `experiment-state` publication is unchanged; evidence publication adds a second barrier between episodes.

[Descriptive] Publication reuses the state publisher's exact-commit confirmation algorithm. Push one fixed child commit by ordinary fast-forward. If the push or acknowledgment fails, wait 10, 30 and 60 seconds before read-only observations. Exact commit means published. Exact parent permits a re-push of that **same SHA**, at most three re-pushes, followed by an immediate observation even if acknowledgment fails. A foreign tip stops immediately; no force, alternate commit, reset or rollback. Every wait, observation and re-push is journaled under `evidence_*` kinds. An exhausted/invalid publication stops `evidence_publication_failed`; an evidence publication or credential failure requires review and is not a permitted automatic-standing stop. An episode's scientific row is retained even if its subsequent publication fails.

## Bound a standing receipt to one approved commit

[Descriptive] An ordinary continuation receipt may additionally contain:

```json
"standing": {
  "max_continuations": 3,
  "allowed_stop_reasons": ["executor_outage", "state_publication_failed"]
}
```

[Descriptive] The allowance counts **new segments under this receipt**, including its explicitly approved segment: three means the approved segment plus at most two automatic successors. Earlier historical continuations do not consume it. For example, if the approved segment is global continuation 3, an allowance of three covers global continuations 3, 4 and 5; it does not authorize 6. Global continuation numbers remain monotonically increasing; the allowance never resets an existing marker. Limits above three, unknown/duplicate stop reasons and malformed policies are rejected. A new allowance requires a new owner receipt; the harness never issues one itself.

[Descriptive] Each successor keeps the same approved code commit, owner, model identities, step and standing policy. It appends the just-closed root checkpoint to the complete ordered source list and advances to the first untouched schedule index, deriving that boundary from touched children, never a model score. The derived receipt records the original complete receipt, its canonical SHA256 and the segment ordinal. The root header retains the actual receipt. Each successor claims its own `continuation-NNNNNN.once` marker with the original receipt hash and ordinal. Every provider request checks the current claim and receipt binding, in addition to the unchanged model/default/cap/freeze guards.

[Descriptive] Before any new claim/request, all prior roots/children must verify, schedule indices must form the exact committed prefix, and the committed native-usage auditor must reconcile every retained settlement/reserve to clean local state **equal to origin**. No pilot reservation may remain open, including an unissued reservation or received but unsettled reply. Historical neutral-check reserves remain in the preserved pre-pilot baseline. A stranded/ahead state commit is not automatically published under standing authority. A failed check stops for review. A successor also checks the last reason against the receipt's allowed list, the same code commit, the prior root's exact receipt derivation and the preceding marker's standing hash/ordinal. No completed or stopped index is executed again.

[Descriptive] An accepted `executor_outage` root without summary/episode_end is supported only when its canonical closed root and closed scoreless child bind the exact next touched index. The child is an operational guard stop, with no inferred score, cost, oracle assessment or synthetic episode_end. All earlier complete rows are checked against their unchanged child episode_end records. This representation is for continuation provenance, not a substitute scientific result row.

[Descriptive] With a standing receipt the CLI's controller can derive the next fresh root after an allowed, fully recorded stop in the same process. The controller has its own evidence chain and stops at completion, the allowance, a disallowed reason or any guard failure. If the executor itself dies, it cannot restart itself: after access is restored and the stopped root has been explicitly closed for review, `--standing-next` accepts the original same-commit standing receipt and **all** prior roots, derives only the next fresh numbered segment, and performs the same checks. It never resumes or repairs a root, closes an outage automatically, changes a marker, or bypasses the need for a verified recorded stop. No infrastructure restart service is installed by this change.
